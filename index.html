    Where we are: it talks, now make it say something useful

    Last class you made a model reply in code. That is the plumbing, and the plumbing is the easy half.

    The gap between a useless AI answer and one you would ship almost never comes down to which model you picked. Two people on the same model, the same free tier and the same task get completely different results. The difference is the prompt.

    Today's page

    Everything in this class works on one piece of text: the readable content of a web page, exactly as it will arrive in your app next class. Notice the cruft. The navigation menu, the "Also read" line, the advert and the copyright notice are what a real scraper hands you, and dealing with them is a prompt problem before it is a code problem.

    02

    The prompt is the product

    A lot of the AI products people pay for are, underneath, the same model you call free from your laptop. No special training, no secret model. What they sell is the prompt wrapped around your input, and a place to type.

    That is not a criticism. It is the opportunity. If the prompt is what makes the product good, prompt writing is product work, and you can do it today with no budget.

    Build a product out of one line

    Same model, same free key, same page text. Only the text above the page changes.

    Important
    Nothing changed except the text above the page. That block is the entire product, and by the end of this class it sits inside your summarizer.py.
    

  
    If it is just a prompt, what stops a competitor copying it? Common doubt
    
    
    Very little, and that is true of most software. What is hard to copy is knowing which rules to write, which comes from watching real users be disappointed. The prompt is cheap to copy and expensive to get right.
    

  
    

    



    
  03
  
    RCTFC: build your summariser's prompt
    
  
    Five parts. Write all five and most prompts come out right the first time.
    
  
    
    
    PartWhat it answersIn your summariser
    
    
    R · RoleWho is writingYou summarise web pages for people deciding whether to read them
    
    
    C · ContextWhat is going on, who reads itScraped page text, shown in an app to someone in a hurry
    
    
    T · TaskThe one thing to doSummarise this page
    
    
    F · FormatThe exact shape of the answerOne opening line, then up to four bullets
    
    
    C · ConstraintsThe limits and the rulesUnder 80 words, keep the numbers, ignore the nav, do not invent
    
  
    
  
    Writing a prompt is writing a good bug report. "The app is broken" gets you nothing. Steps to reproduce, what you expected, what happened and which browser gets you a fix. Same reader, completely different outcome.
    

  
    Build it one part at a time
    
  
    Start with the task alone and add one part per step.
    
  
    
    
    Visualizer · Prompt builderSwitch parts on and off
    
    
    
      
    
      
    
      
    
        
    
        
    
      
    
    
    
  
    
  
    Important
    Order does not matter much. Completeness does. A prompt missing Format is the single most common reason people say the AI did not do what they asked.
    
  
    Format and Constraints do most of the work on routine tasks. Role matters most when tone is the deliverable.
    

  
    Does this mean every prompt has to be long? Common doubt
    
    
    No. It means every prompt has to be complete. "Summarise this page in 3 bullets for someone deciding whether to read it" is short and has Task, Format, Constraints and Context in it. Short and complete beats long and vague.
    

  
    

    



    
  04
  
    Role prompting
    
  
    Role is the part people skip, and it is the cheapest way to change tone and depth in one line. A role does two things: it sets the vocabulary, and it sets what the model thinks is worth mentioning.
    
  
    Summarise the metro page as a commuter and you get times and fares. As a civil engineer and you get elevated stations and the interchange. As an investor and you get passenger numbers. Same page.
    

  
    
    
    Visualizer · Role lensSame page, three readers
    
    
    
      
    
        
        
        
      
    
      
    
      
    
    
    
  
    

  
    Important
    A role changes emphasis and tone. It does not add knowledge the model does not have, and it does not make the model qualified. "You are a doctor" changes how an answer sounds, not whether it is safe to act on. Do not over-trust role prompts.
    
  
    Is "You are an expert" worth adding? Optional doubt
    
    
    Barely. It is too vague to change what the model emphasises. A role earns its place when it implies an audience and a vocabulary. "You summarise pages for people deciding whether to read them" does work. "You are an expert" does not.
    

    



    
  05
  
    Zero-shot and few-shot
    
  
    Zero-shot is instructions with no examples. It is enough for most things. Few-shot is when you paste two or three examples of the output you want, then ask for one more. You are not describing the format any more. You are showing it.
    
  
    The analogy: telling a new joiner "follow our code style" versus opening three of your best pull requests and saying "write it like this". Same person, completely different first attempt.
    

  
    When examples beat instructions
    
  
    Use few-shot when the format is specific to you and hard to describe. You could spend a paragraph explaining the house style of your summaries, or paste two real ones.
    
  
    
    
    Compare · Instructions vs examplesToggle
    
    
    
      
    
        
      
    
      
    
      
    
    
    
  
    
  
    Important
    Two or three examples is the sweet spot. One example and the model treats it as a one-off. Ten and you are paying for tokens you did not need. If quality is still off at three, your examples probably disagree with each other.
    
  
    Does few-shot teach the model permanently? Common doubt
    
    
    No. The examples live in that one prompt and are gone the moment the call ends. Nothing is saved, nothing is trained. This is the no-memory point from Class 1: if you want the examples every time, they have to be in the system prompt your code sends every time, which is what you do in Section 10.
    

  
    

    



    
  06
  
    Structured outputs: asking for JSON
    
  
    So far the output was text for a person. Next class your summary goes into a web interface, and after that people wire these into automations. The moment a program reads the output, the shape has to be exact. Ask for JSON and state the shape.
    
  
    prompt
    Return the summary as JSON with exactly these keys:

{
  "headline": "Pune Metro Line 3 opens Monday",
  "bullets": ["...", "..."],
  "numbers_mentioned": ["Rs 10 to Rs 45", "06:00 to 22:00"],
  "page_type": "news"
}

Rules:
- bullets: between 2 and 4 items, each under 15 words
- numbers_mentioned: copy figures exactly as written on the page, or []
- page_type: one of news, product, blog, documentation, other
- Return only the JSON object. No explanation, no code fences, no preamble.
    
  
    Important
    That last line is the one people forget, and it is why their app breaks. Without it you get a friendly sentence before the JSON, which is not valid JSON, and json.loads fails on character one.
    

  
    
    
    Visualizer · Parser testRuns a real JSON parser in your browser
    
    
    
      
    
        
        
        
        
      
    
      
      
      
    
    
    
  
    

  
    What if it returns JSON that is almost right? Common doubt
    
    
    Tighten the spec rather than fixing the output by hand. Name every key, say what type each one is, and say what to do when the information is missing. Most malformed output comes from a case you did not tell it how to handle, and "use an empty list if there are none" removes the most common one.
    
  
    Paid APIs can also enforce a schema so the response is guaranteed to parse rather than merely asked to. It is the same idea with a guarantee.
    

    



    
  07
  
    Chain-of-thought, and when it still matters
    
  
    Chain-of-thought is one instruction: ask the model to work through the problem step by step before answering.
    
  
    This technique has aged
    A model that is already thinking before it answers does this on its own, and telling it to think step by step adds nothing. A model that is not thinking has no such step, and there the instruction still helps a lot.
    
  
    On gpt-oss that is a dial rather than two different models. Your summariser runs at low reasoning effort, because summarising has no dependent steps, and low effort is exactly where this technique still earns its place. So chain-of-thought is now a decision, not a habit.
    

  
    
    
    Visualizer · Should I add it?Answer two questions
    
    
    
      
    
        
    
          
    
        
    
          
    
      
    
      
    
    
    
  
    

  
    Where it earns its place
    
  
    Summarising a clean article does not need it. Summarising a messy page does. At low effort the plain summary of the metro page usually does fine, though shallow. Now ask the model to work in named stages:
    
  
      
    
    1. Separate the article from the navigation and adverts.
      2. 
    
    2. Identify which numbers affect a reader's decision.
      3. 
    
    3. Write the summary from only those.
      4. 
  
    
  
    On a cluttered page the result is noticeably tighter. The plain version is not wrong; shallow is the thing to watch for.
    

  
    

    



    
  08
  
    Self-critique: let it mark its own work
    
  
    A model is better at spotting a problem in finished text than at avoiding it while writing. That asymmetry is free quality. The pattern has three moves: draft, critique, revise.
    
  
    prompt
    Write the summary.

Then, before showing me anything, check your own draft against these:
- Is every number that affects a decision still in it?
- Did you include anything that is not on the page?
- Did any navigation, advert or "also read" text leak in?
- Is it under 80 words?

List what failed, fix it, and show me only the corrected summary.
    
  
    Important
    The checklist is what makes this work. "Check your work and improve it" produces a paragraph of self-congratulation. Named checks produce real catches, because each one is a question with a yes or no answer.
    

  
    
    
    Visualizer · Run the checklist yourselfIllustrative draft, editable
    
    
    
      
    
      
      
      
    
      
    The fourth check, "anything not on the page", needs a human or the model to compare against the source. The first three are computed live above. Try editing the draft and watch the checks change.
    
    
    
  
    

  
    Is the model actually catching mistakes, or just saying it did? Common doubt
    
    
    Both happen, which is why you ask for the list of what failed. If the critique names a specific line and the revision changes that line, it did the work. If it says "improved clarity and flow" and nothing moved, it did not, and you need sharper checks.
    
  
    A check that belongs on almost every prompt: "Did you make anything up?"
    

    



    
  09
  
    Prompt chaining: one job per prompt
    
  
    When a prompt tries to do four things, it usually does the first well and the rest badly. Chaining splits the work. Each prompt does one job and hands its output to the next.
    
  
    For your app: the first prompt strips the page down to the article and pulls out the facts as JSON. The second turns that JSON into the summary a person reads. The facts cannot drift between them, because the second prompt never sees the messy page.
    

  
    
    
    Visualizer · The chainStep through (illustrative data)
    
    
    
      
    
      
    
    
    
  
    

  
    
    
    Try it · The "and" testOne job or two?
    
    
    
      
    
        
        
        
        
      
    
      
      
      
    
    
    
  
    
  
    Important
    The test for whether to chain: if you can describe the task with the word "and" between two verbs, it is probably two prompts. Extract and summarise. Clean and format. Find and fix.
    
  
    Chaining by hand is tedious, which is why automation tools exist. In Class 6 you build this kind of chain in n8n, where the output of one step drops into the next as a variable. Reusable prompt templates with variables belong there too.
    

  
    

    



    
  10
  
    Put it in code: summarizer.py
    
  
    You have spent an hour getting a prompt right in a chat window, where the loop is three seconds. Now it goes where it will live.
    
  
    The code does three things: holds your prompt as a string, sends it as the system message with the page text as the user message, and returns the reply. It is the same four-step shape from Class 1 with your prompt dropped into the system slot.
    

  
    
    
    Diagram · Two slotsRules in one, page in the other
    
    
    
      
    
        
    system
    Your rules: the prompt you wrote today. Trusted. Sent on every call.
    
        
    user
    "Summarise this page:" plus the page text. Untrusted: it comes from the internet.
    
      
    
    
    
  
    

  
    summarizer.py
    # Your prompt, now in the place that runs it.

import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

key = os.getenv("GROQ_API_KEY")
if not key:
    raise SystemExit("No GROQ_API_KEY found. Is your .env in this same folder?")

client = OpenAI(
    api_key=key,
    base_url="https://api.groq.com/openai/v1",
)

# Everything you wrote in Sections 2 to 8 goes here, between the triple quotes.
SYSTEM_PROMPT = """You summarise web pages for people who are deciding
whether to read them.

Every summary you write:
- opens with the single most useful fact, not a description of the page
- is under 80 words
- uses plain language a commuter would use
- keeps any number that affects a decision: times, fares, dates, distances
- ignores navigation menus, adverts, cookie notices and "also read" links

If the page does not say something, do not fill the gap. Say the page
does not mention it."""


def summarize(page_text):
    response = client.chat.completions.create(
        model="openai/gpt-oss-120b",
        temperature=0.2,            # low: a summary should not vary run to run
        reasoning_effort="low",     # summarising has no dependent steps
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user",   "content": f"Summarise this page:\n\n{page_text}"},
        ],
    )
    return response.choices[0].message.content


# Next class this text arrives from a real web page. For now, paste some in.
if __name__ == "__main__":
    sample = """<paste the metro page text here>"""
    print(summarize(sample))
    

  
    Do it
    
  
      
    
    1. Create summarizer.py in the same folder as your .env from Class 1.
      2. 
    
    2. Replace SYSTEM_PROMPT with the one you wrote today, not the sample.
      3.

      4.

      5. 
  
    
  
    Important
    The temperature is 0.2, not the default. Class 1 taught the dial; this is the first time you use it for a reason. A summary of the same page should not change between runs, so you want the model near the top of its probability list every time.
    

  
    Why is the page text in the user message and the prompt in the system message? Common doubt
    
    
    You could put both together and it would mostly work. Keeping them separate matters for a reason you meet properly next class: the page text is untrusted. It comes from the internet, and anyone can put anything on a web page, including instructions aimed at your model. Keeping your rules in the system slot and the page in the user slot is the first line of that defence.
    
  
    Troubleshooting Common failures
    
    
      
      
    • A stray quote inside your own prompt can break the triple-quoted string.
      • 
      
    • The file must sit in the same folder as the .env.
      • 
      
    • An unexpected keyword error on reasoning_effort means an old openai package. Deleting that one line is harmless: the model uses its default effort. Then run pip install -U openai.

    The techniques, and when to reach for each
    
  
    
    
    TechniqueReach for it when
    
    
    RCTFCAlways. It is the baseline, not a technique.
    
    
    RoleTone or audience keeps coming out wrong.
    
    
    Few-shotThe format is yours and hard to describe in words.
    
    
    Structured outputA program reads the result, not a person.
    
    
    Chain-of-thoughtThe model is not thinking first, or you want to steer which steps happen.
    
    
    Self-critiqueA mistake costs more than a second pass.
    
    
    ChainingThe task description has "and" between two verbs.
